# i-nix

**Imperative UX for declarative Nix/NixOS systems.**

> Imperative commands. Declarative systems.

Use NixOS like a traditional Linux distribution (`apt install`, `dnf install`, `pacman -S`) — but every action automatically becomes part of a clean, reproducible Nix configuration stored in `$HOME/.config/i-nix/flake/`.

---

## What is i-nix?

`i-nix` is **not** another package manager. It is a **UX layer** that compiles imperative commands into declarative NixOS/Home Manager configuration.

```text
USER
 │
 ▼
┌─────────────┐
│    i-nix    │
│             │
│ install     │
│ remove      │
│ enable      │
│ adopt       │
└──────┬──────┘
       │
       ▼
┌───────────────┐
│ Nix config    │
│ SOURCE OF     │
│ TRUTH         │
│ (flake.nix)   │
└───────┬───────┘
        │
        ▼
    nix eval
        │
        ▼
nixos-rebuild
        │
        ▼
  NEW GENERATION
```

## Philosophy

| Traditional Linux | i-nix | Pure Nix |
|---|---|---|
| `apt install firefox` | `i-nix install firefox` | Edit `configuration.nix`, `nixos-rebuild switch` |
| Easy to learn, hard to reproduce | Best of both worlds | Hard to learn, perfectly reproducible |

`i-nix` creates a **gradient**:

```text
Traditional Linux
      │
      ▼
i-nix install firefox
      │
      ▼
See generated configuration.nix
      │
      ▼
User starts modifying Nix directly
      │
      ▼
Full NixOS expertise
```

## Features

- ✅ **`i-nix init`** — Initialize a new declarative configuration (flake-parts + dendritic structure)
- ✅ **`i-nix install <pkg>`** — Add packages to `environment.systemPackages`
- ✅ **`i-nix install --user <pkg>`** — Add packages to `home.packages` (Home Manager)
- ✅ **`i-nix remove <pkg>`** — Remove packages from declarative config
- ✅ **`i-nix search <query>`** — Search nixpkgs
- ✅ **`i-nix list`** — Show all declaratively managed packages
- ✅ **`i-nix diff`** — Show pending changes
- ✅ **`i-nix apply`** — Evaluate and rebuild (with confirmation)
- ✅ **`i-nix rollback`** — Rollback to previous generation
- ✅ **`i-nix adopt`** — Discover current system and generate config (nixify your machine)
- ✅ **`i-nix doctor`** — Diagnose Nix/NixOS installation
- ✅ **`i-nix why <pkg>`** — Show why a package is installed
- ✅ **`i-nix edit <target>`** — Open generated config in `$EDITOR`
- ✅ **`i-nix update`** — Update flake inputs and show available upgrades

## Directory Structure

Production-grade, dendritic, multi-host structure:

```text
$HOME/.config/i-nix/
├── flake/
│   ├── flake.nix              # flake-parts entrypoint (imports ./hosts)
│   ├── flake.lock             # Pinned inputs (nixpkgs, home-manager)
│   │
│   ├── hosts/                 # One file per physical machine
│   │   └── default.nix        # nixosConfigurations registry
│   │
│   ├── systems/               # Per-host system configuration
│   │   ├── _common.nix        # Shared base: boot, locale, nix settings
│   │   └── laptop/            # Host-specific config
│   │       ├── default.nix    #   environment.systemPackages, services
│   │       └── hardware.nix   #   generated by nixos-generate-config
│   │
│   ├── users/                 # Per-user home-manager configs
│   │   └── lin/
│   │       ├── default.nix    # Entrypoint: imports all sub-modules
│   │       ├── packages/      # home.packages (managed by i-nix)
│   │       │   └── default.nix
│   │       ├── programs/      # programs.*.enable (firefox, git, kitty...)
│   │       │   └── default.nix
│   │       ├── services/      # User-level systemd services
│   │       │   └── default.nix
│   │       ├── desktop/       # Desktop Environment / Window Manager
│   │       │   ├── default.nix # Imports chosen DE
│   │       │   ├── gnome.nix  # Generated by nix-my-gnome dconf import
│   │       │   ├── kde.nix
│   │       │   ├── hyprland.nix
│   │       │   └── sway.nix
│   │       ├── shells/        # Shell configuration (bash, zsh, fish)
│   │       │   └── default.nix
│   │       ├── secrets/       # sops-nix or agenix managed secrets
│   │       │   └── default.nix
│   │       └── dotfiles/      # Plain dotfiles (not tracked by HM)
│   │
│   ├── modules/               # Reusable NixOS modules
│   │   ├── system/
│   │   │   └── default.nix    # Network, security, custom modules
│   │   └── home/
│   │       └── default.nix    # Reusable HM modules
│   │
│   ├── profiles/              # Feature bundles (composable)
│   │   ├── core.nix           # Minimal base (ssh, curl, vim)
│   │   ├── desktop.nix        # Full desktop (fonts, pipewire, bluetooth)
│   │   ├── development.nix    # Dev tooling (docker, vscode, git)
│   │   ├── gaming.nix         # Gaming (steam, proton, mangohud)
│   │   └── server.nix         # Server (nginx, postgresql, docker)
│   │
│   ├── overlays/              # nixpkgs overlays
│   │   └── default.nix
│   ├── pkgs/                  # Custom package definitions
│   │   └── default.nix
│   └── lib/                   # Nix helper functions
│       └── helpers.nix
│
└── state.json                 # i-nix metadata (NOT source of truth)
```

### Design Philosophy

1. **Hosts → Systems → Users** (top-down) — Each physical machine has one host file, which imports its system config and user configs.
2. **Profiles** are composable feature bundles — a laptop might import `[core desktop development]`, a server might import `[core server]`.
3. **Users are first-class** — Every user gets their own `users/<name>/` directory with isolated packages, programs, services, desktop, shells, secrets.
4. **Desktop is separate** — DE/WM configs live in `desktop/` and can be swapped by changing one import in `users/<name>/desktop/default.nix`.
5. **nix-my-gnome compatible** — `users/<name>/desktop/gnome.nix` is where your dconf-to-Nix import goes.

## Quick Start

```bash
# 1. Initialize i-nix
i-nix init --hostname my-machine --system

# 2. Install packages
i-nix install firefox git vim ripgrep
i-nix install --user kitty neovim starship

# 3. See what changed
i-nix diff

# 4. Apply changes
i-nix apply
```

## Design Principles

1. **Nix remains the source of truth** — The generated `.nix` files are canonical. `i-nix` modifies them; experienced users edit them directly.
2. **One desired state. Two interfaces.** — Imperative CLI and declarative files both modify the same Nix configuration.
3. **No TOML/YAML state files** — Pure Nix. No secondary configuration language.
4. **Dotfiles where they belong** — For complex configs (editors, terminals), use plain dotfiles managed via `home.file`, not brittle HM options.
5. **Organic learning** — Start with `i-nix install firefox`, graduate to editing `configuration.nix` directly.
